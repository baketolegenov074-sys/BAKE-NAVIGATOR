# BAKE Navigator — автоматическая диагностика

## Поток отчётов

1. Приложение записывает необработанные Flutter- и платформенные ошибки.
2. GPS-диагностика отправляет только аномалии: задержки callback/fix, скачки расстояния, плохую точность и ошибки GPS-потока.
3. Если интернета нет, до 100 отчётов остаются в локальной очереди телефона.
4. После успешной записи в Supabase приложение вызывает Edge Function `github-issue-from-diagnostic`.
5. Функция проверяет запись на сервере и создаёт GitHub Issue в `baketolegenov074-sys/BAKE-NAVIGATOR`; номер и URL Issue записываются обратно в Supabase.
6. Если сеть или GitHub недоступны, запись остаётся в локальной очереди и повторяется при следующей попытке синхронизации. Повторные вызовы не должны создавать второй Issue для того же ID.

## Данные

- категория, время, версия приложения и платформа;
- тип ошибки и стек вызовов;
- технические метрики GPS без координат.

Координаты и адреса маскируются повторно на сервере. Из details удаляются поля с названиями lat/lon/coord/address/route/query/destination. GitHub Issues не получают сырые координаты.

## Настройка единственного секрета

В Supabase Dashboard откройте **Edge Functions → Secrets** и добавьте:

- `GITHUB_TOKEN` — Fine-grained Personal Access Token только для репозитория `baketolegenov074-sys/BAKE-NAVIGATOR`, разрешение **Issues: Read and write**.

Токен хранится только в Supabase Edge Function и никогда не включается в APK или Git. Существующие `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` и ключи проекта доступны функции из окружения Supabase.

Если секрет не задан, функция отвечает `503 server_secrets_not_configured`; локальная очередь не очищается, отчёт не теряется.

## Ограничения и защита

- RLS таблицы `app_error_reports` остаётся включённым; клиенту разрешена только вставка.
- Публичное чтение, изменение и удаление таблицы запрещены.
- Функция принимает только ключ проекта в заголовке `apikey`, читает отчёт серверным ключом и повторно фильтрует чувствительные поля.
- Ограничение автоматической публикации: не более 12 Issues за час.
- Идентификатор отчёта добавляется в Issue как маркер для поиска уже созданной записи.
- OpenAI API не используется. ChatGPT может анализировать созданные Issues через подключённый GitHub в открытом чате; постоянного фонового наблюдения со стороны ChatGPT нет.

## Проверка

После добавления `GITHUB_TOKEN` и следующей сборки APK нужно отправить тестовую ошибку и убедиться, что:
1. строка появилась в `app_error_reports`;
2. создан GitHub Issue с маркером `BAKE-DIAG-ID`;
3. в Supabase заполнены `github_issue_number`, `github_issue_url`, `github_synced_at`.

APK, Flutter analyze и runtime-тест пока не запускались.
